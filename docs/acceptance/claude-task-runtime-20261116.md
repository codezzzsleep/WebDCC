# Claude 任务运行实例边界（#221）

锁定 SDK `0.3.322` / CLI `2.1.322` 会在同一 query 后续轮次再次发送 `system/init`。实际原生停止回放中，A 收到 `stopped` 后 B 仍运行；旧投影却因重复 init 把 B 改为 unknown。

WebDCC 现在保存独立的 query 实例身份及不可用信号，原始 SDK 消息保持原样。同实例的 init 保留任务状态；新实例启动、流结束或关闭会使先前活动任务待确认，并保留已完成、失败、停止的证据。后台快照只证明成员身份，不能把旧实例的生命周期恢复成运行；需要当前实例的任务开始、进度、状态或终态通知。缺少实例元数据的旧记录仍按未知进程边界保守恢复。

本地源码检查通过 107 项 Claude/protocol 回归、adapter/server/web 类型检查及改动 Lint。其中实际 SDK 初始化、stdio 和临时历史文件合同不提交模型轮次；生命周期回归使用受控 SDK 形状消息。Chromium 源码浏览器验证同实例重复 init、A 停止后 B 保持运行、不可用后的未知状态、终态保留、刷新、重连、会话切换和 390px 独立入口。

另重放先前实际 SDK 双任务运行捕获的 68 帧原生消息，其中同一进程有两次 init；A 保持 stopped、B 保持 running，adapter、存储恢复和公共任务视图一致，新增模型请求为 0。该检查没有启动新 SDK 进程，也不证明当前 provider 或目标平台。原始付费任务失败、回放验证器失败与未录制的模型续答全部保留；单任务停止可用性仍为 false，待后续专项验证实际控制链路。
