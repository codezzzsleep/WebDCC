# 发布失败与数据库兼容

`pnpm release` 在候选产物启动前核对上一产物的 `packages/server/dist/build-manifest.json`。当前数据库及候选可能迁移出的最高 schema 必须处于上一产物声明的 `database.minimum`–`database.maximum` 内。清单缺失、损坏或范围不兼容会取消发布，保留 current 和运行中的服务。

因此，这个带自动回滚的入口会拒绝上一产物不能读取的 schema 升级。需要升级数据库时，应单独设计并验收迁移和恢复过程，再使用支持目标 schema 的回滚产物；备份存在不能证明旧服务可读取迁移后的库。

候选服务重启后，认证与提交复核失败会触发回滚。脚本再次读取实际数据库版本和上一产物清单，兼容时切回旧产物并重启。数据库和重启后新增的数据保持原样，脚本不会用旧备份覆盖它们。

无法证明兼容时，脚本不启动旧产物，尝试停止服务，保留 current 指向候选以便核对迁移后的库，并以非零状态报告原发布错误及回滚失败。停止服务本身失败也保留在错误中，必须核对实际服务状态。首次发布没有旧产物时，失败会移除 current 并停止服务，保留数据。

这些检查不能替代服务排空和目标平台恢复验收。并发数据库写入、外部迁移、真实 systemd、各 Agent 的原生进程与会话恢复需要独立验证。`scripts/release-rollback.spec.ts` 使用真实临时 SQLite、生产发布入口，以及受控构建、服务命令和本机 HTTP；它不部署或启动实际 Agent。
