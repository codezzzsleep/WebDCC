# Codex Watchdog

在侧边栏打开“Watchdog 看门狗”，开启 **Codex 自动恢复**。这是服务端持久化的全局开关，默认关闭，适用于 WebDCC 管理的所有 Codex 会话。外部终端中的独立 Codex 任务不在此范围。开关只处理启用后新发生的失败，不会追溯启动历史失败任务。

限流或流中断的一轮明确失败后，Watchdog 按指数退避和随机延迟等待，尊重服务端给出的更长等待，再向原会话发送继续任务的消息。Codex 自己仍在重试时，Watchdog 不发送第二轮。默认初始等待 30 秒，最大退避 900 秒，最多自动恢复 5 次。

当终止错误明确表示 Responses 历史项属于另一个 OpenAI 资源时，Watchdog 通过普通会话创建流程调用 `thread/start`，建立独立的新会话。它保留原工作目录、Provider、模型、思考等级和访问模式，用 `parentId` 关联来源，并把任务、近期进展和完整文字交接记录的路径发给新会话。记录保存在私有数据目录 `watchdog/<来源会话>/<失败轮次>.md`，包含原始用户要求和可读进展。原生请求 item、加密 reasoning 和旧图像不会被重放到新的请求历史中。交接次数默认最多 2 次，且继承同一任务链的恢复预算，避免连续创建无限会话。

会话状态栏和设置页显示等待时间、恢复次数、结果和接续会话入口。用户手动发送消息、停止会话、归档或取消后续恢复，都会取消待执行的恢复。关闭全局开关取消等待和尚未提交的请求；已经开始的轮次通过该会话的停止按钮打断。审批或提问仍需用户处理。Watchdog 不处理认证、余额、权限和未知错误。

等待队列与配置保存在 SQLite，服务重启后可继续等待。若进程恰好在提交恢复请求时退出，无法确定该请求是否执行，记录会停止自动重发并要求核对进度，避免重复外部操作。

此功能自动接续工作，不修改供应商账号或资源路由；底层资源归属问题仍可能再次出现。默认关闭，开启后自动继续和新会话交接会产生模型用量。

协议依据：[Codex App Server 官方文档](https://learn.chatgpt.com/docs/app-server)中的 `willRetry`、终止状态、`thread/start` 与 `thread/fork` 语义。故障判断还依据本机用户会话的实际终止错误调查。

验证使用假 adapter 的实际终止生命周期、持久化队列、关闭/手动介入/创建竞态与交接预算测试，以及本地浏览器开关、原会话续跑、新会话交接和取消操作；不请求真实模型。开发阶段不部署、不重启生产服务。
