# Codex Watchdog

在侧边栏打开“Watchdog 看门狗”，开启 **Codex 自动恢复**。这是服务端持久化的全局开关，默认关闭，适用于 WebDCC 管理的所有 Codex 会话。外部终端中的独立 Codex 任务不在此范围。开启后处理新发生的失败；放宽恢复上限时，也会接续此前确实因该上限耗尽而停止的任务。已取消、已归档和结果不确定的任务不会因此自动重启。

限流或流中断的一轮明确失败后，Watchdog 按指数退避和随机延迟等待，尊重服务端给出的更长等待，再向原会话发送“继续”。Codex 自己仍在重试时，Watchdog 不发送第二轮。默认初始等待 30 秒，最大退避 900 秒。

续跑和转交均默认不限次数，用户可分别取消对应的“不限次数”选项，填写 10、100、1000 等有限次数；平台不再设置 10 次、3 次的业务上限，也不要求两项上限互相约束。API 用 `maxAttempts: null` / `maxHandoffs: null` 表示不限，整数表示各自上限（续跑为正整数，转交为非负整数，0 表示不自动转交）。两项独立计数。不限模式同样保持退避等待，可随时关闭或取消。

当终止错误明确表示 Responses 历史项属于另一个 OpenAI 资源时，Watchdog 调用 `thread/start` 建立独立的新会话，保留原工作目录、Provider、模型、思考等级和访问模式。新旧会话在侧栏平级展示，来源链接继续保留。发送给新会话的内容只有旧 Codex ID、读取完整上下文后继续的短提示，以及会话记录位置；不再注入任务和进度长摘要。

记录优先指向本机旧会话的原生 rollout；找不到原生记录时，使用私有数据目录 `watchdog/<来源会话>/<失败轮次>.md` 的可读记录。记录由新会话按需读取，不作为旧 Responses item 重放。同一任务链保留续跑和转交的各自计数；来源链接用于查阅记录，平级会话分别操作，停止旧会话不会连带停止新会话。

会话状态栏和设置页显示等待时间、恢复次数、结果和接续会话入口。用户手动发送消息、停止会话、归档或取消后续恢复，都会取消待执行的恢复。关闭全局开关取消等待和尚未提交的请求；已经开始的轮次通过该会话的停止按钮打断。审批或提问仍需用户处理。Watchdog 不处理认证、余额、权限和未知错误。

等待队列与配置保存在 SQLite，服务重启后可继续等待。若进程恰好在提交恢复请求时退出，无法确定该请求是否执行，记录会停止自动重发并要求核对进度，避免重复外部操作。

此功能自动接续工作，不修改供应商账号或资源路由；底层资源归属问题仍可能再次出现。默认关闭，开启后自动继续和新会话交接会产生模型用量。

协议依据：[Codex App Server 官方文档](https://learn.chatgpt.com/docs/app-server)中的 `willRetry`、终止状态、`thread/start` 与 `thread/fork` 语义。故障判断还依据本机用户会话的实际终止错误调查。

验证使用假 adapter 的终止生命周期、超过十次的持续恢复、有限次数转无限后的接续、等待时间溢出、关闭/手动介入和转交预算测试，以及浏览器无限开关、平级展示、短交接和取消流程。测试不请求真实模型。
