# Native protocol type boundary

The pinned Codex TypeScript export is generated by ts-rs with extensionless type imports. It was previously excluded and unused, so the old NodeNext check did not validate native request fields.

Use the existing bundler toolchain's module resolution (`ESNext` / `Bundler`) for source type checking. Server output continues to be ESM built by esbuild for Node 24; scripts continue to run through tsx. Original generated schemas are unchanged. This lets every source consumer use the exported native types rather than copying them or suppressing compiler errors.

Known outgoing requests use those types plus runtime validation from the pinned combined JSON schema. Outgoing parameter objects reject unexpected fields at the client boundary. Incoming results retain native extension fields. Both requests and responses, including initialization, use definitions from the original native export.

Authenticated file responses identify safe raster formats from bytes; other content downloads with `nosniff` and a sandbox CSP. Named public deployments declare `WDCC_PUBLIC_ORIGINS`; forwarded protocol headers are trusted only from `WDCC_TRUST_PROXY`. Proxies must preserve the external Host header.
