# 原生 Skill 首条输入与分叉续聊

本轮面向个人使用 Codex、Claude Code、DSH 的网页工作流程，关联 #67、#69 和具体缺陷 #382。T3 Code 只用于了解同类产品的目录绑定方式；本项目继续使用现有技术栈和各 Agent 的官方运行机制。

## 网页操作

- 新建 Codex 会话时，先选工作区，再从附件菜单选择“添加原生技能”。第一条消息即可携带该 Skill；读取目录不创建会话或发送模型消息。禁用 Skill 不能选择，切换工作区后不会插入旧目录的迟到结果。
- 在已连接的原生会话中打开“原生控制”，提交分叉。确认完成后，点击“在分叉会话中继续”；网页关联官方返回的新原生会话，后续输入恢复该会话。来源会话、草稿和队列继续保留。
- 分叉回执和网页关联一起持久化。响应丢失或刷新后可以恢复入口，同一命令不会重复分叉。若原生结果或关联无法确认，保留不确定状态并阻止盲目重试。

Skill 的 name/path 仍由 Codex 当前原生目录解析和校验，网页保留正文与结构化引用。Claude Code、DSH 的 Skills 继续使用其原生配置与命令。

## 原生连接

Codex 使用官方 `skills/list`、`thread/fork` 和 `thread/resume`。分叉会在来源 app-server 加载新的 writer，因此只对返回的新会话调用 `thread/unsubscribe`，等待对应 `thread/closed` 后再允许独立恢复。官方默认空闲释放约 60 秒；网页等待上限为 90 秒，超时保留未确认结果。不会改变原生保留时间或关闭来源会话。

Claude Code 使用官方 SDK `forkSession`。来源 query 已接受的启动配置保留来源身份，新 query 初始化成功后才建立自己的配置接受记录。DSH 使用官方 `session/fork` 并读取新会话的实际模型投影；无法确认模型路由时保留原生选择，权限继续沿用原生设置。

DSH `settings/describe` 的 schema UID 属于内部编号。仅对目录比较规范化实际 schema 引用图，默认值、规则、配置修订、Host 和会话状态仍参与校验。公开目录继续经过既有脱敏；原生输入和目录内容不被改写。
