# 界面：三个 Harness 怎么摆、怎么切

这份文档说明 `ui/dsh-design` 这一版界面的设计决定。后续改界面先读它；要推翻其中某一条，先在 PR 里写清楚理由。

## 1. 视觉基线：照 DSH 原版

- 颜色、字号、圆角、间距都来自 DSH 客户端的设计变量（`packages/web/src/styles/tokens.css`，MIT，文件头有出处）。不自己发明配色。
- 品牌字体 Montserrat（OFL，`public/fonts/`）只用在左上角的 WebDCC 字标上。正文用系统字体栈，和 DSH 一样。
- 亮色、暗色跟随系统（`prefers-color-scheme`）。
- 图标统一走 `components/Icon.tsx`（线性图标，1.8 线宽）。不要再用 emoji 或字符当图标。

## 2. 三个 Agent 是平级的"执行者"，不是三个产品

- 每个会话**固定**属于一个 Agent，创建后不能换。原因：三个 Agent 的会话历史、工具、权限模型互不相通，偷偷"换芯"会让上下文和审批状态都对不上。
- Agent 用一个两字母的单色标识（`DS` / `CX` / `CC`，`components/AgentMark.tsx`）表示，出现在：侧边栏每一行、会话头、输入框的 Agent 胶囊、停靠区标题。**不用颜色区分 Agent**，颜色留给状态（运行中、待批准、出错）。
- 输入框底部一排胶囊：`Agent` · `访问模式` · `模型`。三者并列，是"这一条消息由谁、以什么权限、用哪个模型来做"。
  - 新会话页：三个都能改；Agent 也可以用上方三张卡片选。上次选的 Agent 记在浏览器里。
  - 会话页：Agent 胶囊带锁，点开只有"在 X 中继续…"；访问模式随时可改；模型只能在同一 Provider 内换（换 Provider 要开接续会话）。

## 3. 换 Agent = 开一个接续会话

用户想"让另一个 Agent 接着干"时：

1. 在 Agent 胶囊菜单里点"在 Codex 中继续…"，或在某条回答下点"带到…" → "在另一个 Agent 中继续"。
2. WebDCC 新建一个会话：同一工作区、目标 Agent、`parentId` 指向原会话。
3. 原会话最后一条回答（或被"带到…"的那条）**原文**放进新会话的输入框，**不自动发送**。用户可以先改再发。
4. 新会话顶部有一条"接续自 …"的提示条，可以一键把原会话并排放到右侧对照。
5. 侧边栏里接续会话缩进挂在原会话下面，形成一条链。

不做"自动摘要后交接"：哪些上下文该带过去由用户决定，WebDCC 不替用户改写任何一个 Agent 的输入。

## 4. 模型菜单：按来源分组

模型胶囊打开后是分组列表：

- 第一组是这个 Agent 的**原生**登录（Codex 的 ChatGPT 登录、Claude 的 Claude 登录、DSH 自己设置里的模型）。
- 后面每个 Provider 一组（从本机配置导入的、或手动添加的）。和当前 Agent 协议不兼容的组灰显，并写明原因（例如"没有 Anthropic 兼容地址，Claude Code 用不了"）。
- Provider 没有模型列表时，组里给一个输入框，填模型名回车。
- Codex 用非 OpenAI 模型又没有模型目录时，输入框下方提示"需要模型目录，否则工具可能不可用"。

## 5. 一轮对话的样子（照 DSH）

- 用户消息靠右气泡；Agent 的一轮是一个块：运行中显示"运行中…"，卡在审批或提问上显示"等你处理"。
- 一轮结束后折叠成一行"已完成，用时 X"+ 一句摘要（执行了几条命令、读了哪些文件、改了哪些文件），下面只留最终回答、改动卡片和需要你处理的卡片。点标题展开全部步骤。
- 审批卡片：标题 + 命令原文 + 折叠的"详情"。处理后收成一行"已允许一次：…/已拒绝：…"。
- 任务条放在输入框上方：DSH 的任务、Claude 的 Todo、Codex 的计划都显示在这里；Codex 的目标单独一行。

## 6. 并排

会话头的"并排"菜单列出同一工作区的会话（标出"上一棒/下一棒"）和"工作区文件"。右栏只读对照；要给它发消息就"移到主栏"。宽度小于 1024 时右栏全屏覆盖，左上角返回。

## 7. 断点

- ≥1024：侧边栏 + 主栏 (+ 右栏)。
- 768–1023：侧边栏默认收成 56px 窄栏。
- <768：侧边栏变抽屉，会话头左侧按钮打开。
